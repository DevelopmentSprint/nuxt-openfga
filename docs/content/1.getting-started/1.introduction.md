`@developmentsprint/nuxt-openfga` connects a Nuxt 4 application to
[OpenFGA](https://openfga.dev), the relationship-based authorization server
inspired by Google Zanzibar.

- **Server helpers** for checks, writes and `listObjects`, auto-imported into
  Nitro, with a per-process decision cache.
- **Route guards** (`requireRelation`) that respond 401, 400 or 403 before your
  handler runs.
- **UI gating** with a `<Can>` component and `useCan` composable, resolved
  during SSR so gated content does not pop in after hydration.
- **Contextual tuples** so role facts you already store reach OpenFGA without
  being duplicated as tuples.
- **Memory mode**: an in-memory evaluator for tests and local development with
  no OpenFGA server. CI checks it against a real OpenFGA server.
- **Optional model deployment** of your `.fga` file when the server starts, for
  servers that accept DSL bodies.

## What your application supplies

The module has no knowledge of your model's types. Your application supplies:

- the **authorization model** and the **tuples**, written with the helpers or
  any OpenFGA client;
- **authentication**: the module reads the signed-in user's id from the
  request, and does not log users in. See
  [Authentication](/getting-started/authentication).

## Requirements

- Nuxt 4
- Node.js 22 or later
- An OpenFGA server or a compatible managed service. Memory mode needs none.
