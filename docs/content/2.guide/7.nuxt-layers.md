The module works from a [Nuxt layer](https://nuxt.com/docs/getting-started/layers).
A shared layer can install it, set its options and provide the authentication
middleware, so every app that extends the layer gets `/api/_authz/check`, the
server helpers, `<Can>` and `useCan` without configuring them again.

## Install the module in the layer

List the module in the layer's `nuxt.config.ts`, by package name, and add it to
the layer's `dependencies` (not `devDependencies`), so it is installed with the
layer:

```ts [layers/base/nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@developmentsprint/nuxt-openfga'],
  openfga: {
    userIdPath: 'auth.userId',
    contextualTuplesKey: 'roleTuples',
  },
})
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: ['../layers/base'],
  // No openfga key needed: the layer's options apply.
})
```

::note
Nuxt resolves a **relative** module path in a layer's config from the
extending app's directory, not the layer's. Use the package name, or an
absolute path such as `fileURLToPath(new URL('../src/module', import.meta.url))`.
::

An app that also lists the module in its own `modules` is fine: Nuxt installs
it once.

## How options merge

Nuxt merges each layer's `nuxt.config` into the app's:

- **The app wins over its layers**, and a layer wins over the layers it extends.
  An app can override a single option, such as `cacheTtlMs`, and keep the rest
  from the layer.
- **Objects merge key by key.** An app can override one entry in a layer's
  `headers`, but not remove an entry the layer sets.
- **Environment variables win over every layer** at runtime, for the options
  that have one (the URL, store, model, headers and model file). See
  [Configuration](/reference/configuration#environment-variables).

Keep the OpenFGA URL, store id and credentials out of a layer you publish. Set
them per app and environment with environment variables.

## Authentication middleware

The middleware that sets the session user on `event.context` can live in the
layer or in the app. Server middleware from every layer runs before
`/api/_authz/check` and your routes, so `userIdPath` and `contextualTuplesKey`
only have to match whatever that middleware sets. See
[Authentication](/getting-started/authentication).

## What each app still provides

- **The axios override.** Package-manager overrides only apply in the root
  project, so a layer cannot set one for the apps that use it. Add it to each
  app, as in [Installation](/getting-started/installation#lift-the-axios-version).
- **The model file, if you use `autoDeployModel`.** A relative `modelFile` is
  resolved against the server's working directory when it starts, not against
  the layer. Keep the `.fga` file in the app, or set `OPENFGA_MODEL_FILE` in
  each deployment. An absolute path set in the layer points at the build
  machine, so it breaks once the app is deployed.
