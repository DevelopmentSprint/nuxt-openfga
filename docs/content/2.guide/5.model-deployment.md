## With the `fga` CLI

Deploy your model with the [`fga` CLI](https://github.com/openfga/cli), as
with any OpenFGA application:

```bash
fga model write --store-id "$OPENFGA_STORE_ID" --file openfga/model.fga
```

## At server startup

If your server accepts DSL bodies on
`POST /stores/:storeId/authorization-models` with
`Content-Type: application/x-openfga-dsl`, the module can deploy for you
instead. Set `autoDeployModel: true`, and a Nitro startup plugin reads
`modelFile`, sends it, and uses the returned model id.

::warning
**The upstream OpenFGA server accepts only JSON models**, which is why
`autoDeployModel` is off by default.
::

The plugin sends an `Idempotency-Key` derived from the file's contents, so
servers that honor the key do not create a new model on every restart.

It reads `apiUrl`, `storeId` and `modelId` from environment variables or
`nuxt.config`, like the server helpers. It skips deployment when:

- a model id is pinned (`OPENFGA_MODEL_ID` or `modelId`);
- `OPENFGA_MODE=memory`;
- the URL or store id is missing.

Failures are logged and do not stop the server; checks fail until the model is
available.

In production, the model file is read from disk at startup. Make sure it is
present relative to the server's working directory, or set
`OPENFGA_MODEL_FILE` to an absolute path.
