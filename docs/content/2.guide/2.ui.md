## `<Can>`

```vue
<template>
  <Can relation="editor" object-type="document" :object-id="doc.id">
    <EditButton />
    <template #fallback>
      <span>Read only</span>
    </template>
  </Can>
</template>
```

`<Can>` renders its default slot when the check allows, `#pending` while the
check is in flight, and `#fallback` otherwise. Both named slots default to
nothing.

## `useCan`

`useCan` is the composable underneath. Its arguments may be refs or getters,
and the check reruns when they change:

```ts
const { allowed, pending, error, refresh } = useCan('editor', 'document', () => props.id)
```

## The check endpoint

Both call `POST /api/_authz/check`, which the module registers. The endpoint
only answers questions about the signed-in user, and ignores any subject in
the request body. Checks run during SSR, and components asking the same
question on one page share a single request.

The endpoint applies OpenFGA's own field limits and responds 400 to anything
OpenFGA would reject:

| Field | Limit |
|---|---|
| `relation` | Up to 50 characters, without `:`, `#`, `@` or whitespace. |
| `objectType` | Up to 254 characters, without `:`, `#`, `@` or whitespace. |
| `objectType:objectId` | Up to 256 characters, without whitespace. |

This keeps arbitrary input out of the shared decision cache without rejecting
any id OpenFGA accepts.

::warning
**Hiding UI is not access control.** Every endpoint that returns or changes
protected data must still enforce the relation with `requireRelation` or
`checkAccessOrThrow`.
::
